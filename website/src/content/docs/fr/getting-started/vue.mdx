`@dzcalendar/vue` fournit un composant `<DzCalendar>` pour Vue 3.4 et 3.5.

## Installer

```sh
npm install @dzcalendar/core @dzcalendar/dom @dzcalendar/theme @dzcalendar/vue
```

Importez la feuille de style une fois, et fixez les valeurs par défaut de
chaque calendrier avec le plugin (facultatif) :

```ts
import { createApp } from 'vue';
import '@dzcalendar/theme/dzcalendar.css';
import { DzCalendarPlugin } from '@dzcalendar/vue';
import '@dzcalendar/core/recurrence'; // les événements répétés (rrule)
import App from './App.vue';

createApp(App)
  .use(DzCalendarPlugin, { defaults: { timeZone: 'Europe/Paris', locale: 'fr-FR' } })
  .mount('#app');
```

## Temporal d'abord

`<DzCalendar>` attend Temporal de lui-même, mais votre propre code crée aussi
des valeurs Temporal (un `ref` qui tient une date, dans `<script setup>`). Sur
un navigateur sans Temporal natif (Safari, tous les navigateurs iOS), son
polyfill arrive avec `loadTemporal()` : attendez-le une fois dans `main.ts`,
avant le montage.

```ts
import { createApp } from 'vue';
import { loadTemporal } from '@dzcalendar/core';
import App from './App.vue';

// Tout de suite si le navigateur a Temporal (Chrome, Edge, Firefox) ; Safari charge d'abord son polyfill.
await loadTemporal();
createApp(App).mount('#app');
```

## Un calendrier

```vue
<script setup lang="ts">
import { ref, shallowRef } from 'vue';
import { Temporal } from '@dzcalendar/core';
import type { EventInput, PlainDate, Selection } from '@dzcalendar/core';
import { DzCalendar, createCalendarController } from '@dzcalendar/vue';
import '@dzcalendar/core/recurrence'; // les événements répétés (rrule)

const cal = createCalendarController();
const view = ref('timeGridWeek');
const date = shallowRef<PlainDate>(Temporal.PlainDate.from('2026-10-21'));
const selection = shallowRef<Selection | null>(null);
const events = shallowRef<EventInput[]>([
  { id: 'a', title: 'Consultation', start: '2026-10-21T09:00[Europe/Paris]', duration: { minutes: 45 } },
  { id: 'b', title: 'Appel Chicago', start: '2026-10-22T10:00[America/Chicago]', duration: { hours: 1 } },
  { id: 'c', title: 'Congé', start: '2026-10-23', allDay: true },
  { id: 'w', title: 'Visite', start: '2026-10-19T08:00[Europe/Paris]', duration: { hours: 2 }, rrule: 'FREQ=WEEKLY;BYDAY=MO,WE' },
]);
</script>

<template>
  <header>
    <button @click="cal.prev()">‹</button> <h2>{{ cal.title.value }}</h2> <button @click="cal.next()">›</button>
    <button :disabled="!cal.canUndo.value" @click="cal.undo()">Annuler</button>
  </header>
  <DzCalendar
    :controller="cal"
    time-zone="Europe/Paris"
    locale="fr-FR"
    :events="events"
    v-model:view="view" v-model:date="date" v-model:selection="selection"
    editable selectable
    @event-click="(instance) => console.log(instance.event.id)">
    <template #event-content="{ event, ctx }"><b>{{ event.title }}</b> {{ ctx.timeText }}</template>
  </DzCalendar>
</template>
```

## Comment se comportent les props

- **Des props** pour les options courantes (`events`, `sources`,
  `resources`, `timeZone`, `locale`, `axis`, `editable`, `selectable`,
  `businessHours`, `weekends`, `weekNumbers`, `hiddenDays`, `messages`,
  `theme`, `scheme`, `density`, `displayCalendar`, `secondaryCalendar`,
  `availableSlots`) ; **`options`** pour tout le reste de ce que prend
  `update()` (`headerToolbar`, `nowIndicator`, `dayMaxLanes`…) ;
  **`initial`** pour ce qui est lu une fois (`firstDay`, `rules`, `now`…).
- Les tableaux et les objets sont comparés par leur contenu ; les sources par
  identité (gardez leurs spécifications stables).
- **Donnez un nouveau tableau pour changer les événements**
  (`events.value = [...events.value, e]`) : un `push` sur le même tableau
  n'est pas vu.
- Une prop qui revient à `undefined` laisse la valeur du calendrier telle
  quelle.

<Aside type="caution">
`view` et `date` liées **sans** leur gestionnaire `update:` l'emportent : le
calendrier y revient après qu'une personne a navigué. Utilisez `v-model:view`
et `v-model:date` (comme ci-dessus) pour que les boutons de l'en-tête
fonctionnent.
</Aside>

## Événements

`@date-click`, `@event-click`, `@event-open`, `@create-request`, `@selected`,
`@slot-click`, `@source-notice`, `@problems`, `@resource-problems`,
`@dropped`, `@event-receive`, `@event-leave`, `@error` (une valeur que le
calendrier a refusée ; non écouté, il va à `app.config.errorHandler`, sinon à
la console), et **`@event-change`** : ce qu'une personne a modifié (un
glisser, un redimensionnement, le clavier, le menu, l'éditeur).
Enregistrez-le, et appelez `change.revert()` si le serveur refuse.

`@event-open`, `@create-request` et `@slot-click` changent ce que le
calendrier propose (« Ouvrir » dans le menu…) : ils ne sont proposés que tant
qu'ils sont écoutés.

## Slots

- **`#event-content="{ event, ctx }"`** : vos composants, téléportés dans
  chaque événement — vos provides, votre store, votre routeur et votre i18n
  les atteignent.
- **`#day-header="{ day }"`** : l'en-tête de chaque jour (`day.date`,
  `day.resource`, `day.lengthMinutes`, `day.text`).
- Un slot pour chaque élément qui a un contenu, chacun recevant `{ ctx }` :
  `#day-cell`, `#slot-label`, `#all-day-label`, `#more-link`,
  `#now-indicator`, `#week-number`, `#no-events`, `#list-day-header`,
  `#month-header`, `#resource`, `#resource-group-header`,
  `#resource-area-header`.
- **`#header-item-<nom>="{ ctx }"`** : votre place dans l'en-tête, nommée
  dans `headerToolbar`
  (`:options="{ headerToolbar: { end: 'filter timeGridWeek' } }"` →
  `#header-item-filter`).
- **`:hooks="{ dayCell: { class: … } }"`** : des classes et des montages pour
  n'importe quel élément, fusionnés avec les slots.

## Le contrôleur

`createCalendarController()` à côté du calendrier, ou
`injectCalendarController()` dans un composant placé dedans (le contenu d'un
événement). Refs : `title`, `view`, `date`, `range`, `canUndo`, `canRedo`,
`loading`, `problems`, `instance` ; méthodes `prev`, `next`, `today`, `goTo`,
`changeView`, `dispatch`, `undo`, `redo`, `refetch`.

## Rendu serveur

Importer les paquets ne touche ni `document` ni `window` ; le calendrier n'est
créé que dans le navigateur (`onMounted`).

## Le Pro

```ts
import '@dzcalendar/pro';                     // les vues timeline
import { useDzExport, useEventEditor } from '@dzcalendar/pro-vue';

const cal = createCalendarController();
useEventEditor(cal, { onClosed: (outcome) => console.log(outcome) });
const exports = useDzExport(cal);   // exports.download('pdf', 'agenda.pdf')
```
