Les ressources sur lesquelles les événements sont réservés — un médecin, une salle, une machine — dessinées en colonnes par les vues ressources.

<OptionFacts name="resources" />

## Ce qu'elle fait

Une ressource est `{ id, title }` et, au besoin :

- `parentId` : un arbre (un service au-dessus de ses médecins) ; `order` : les
  ressources sœurs d'abord selon ce nombre.
- `timeZone` et `businessHours` : ses propres heures, lues dans son propre
  fuseau (un médecin à Riyad sur un calendrier affiché à Paris).
- `eventConstraint`, `eventOverlap` : ses propres règles, au-dessus de celles
  du calendrier.
- `classNames`, `extendedProps`, et tout champ à vous (pour trier ou grouper).

Un événement va sur une ressource avec `resourceId` (ou sur plusieurs avec
`resourceIds`). Les vues ressources — `resourceTimeGridDay`,
`resourceTimeGridWeek`, `resourceDayGridDay`, `resourceDayGridWeek`,
`resourceDayGridMonth`, et les `resourceTimeline…` du Pro — dessinent une
colonne (une ligne dans la timeline) par ressource ; un événement sur deux
ressources est dans les deux. Les autres vues ignorent les ressources.

Une mauvaise donnée ne lève jamais d'exception : ce qui ne se lit pas va à
`onResourceProblems`. `update({ resources })` remplace la liste ; le même
tableau ne change rien.

## Exemple

<CodeTabs>
<Fragment slot="js">

```ts
import { createCalendar } from '@dzcalendar/dom';

const calendar = createCalendar(element, {
  timeZone: 'Europe/Paris',
  initialView: 'resourceTimeGridDay',
  resources: [
    { id: 'benali', title: 'Dr Benali' },
    { id: 'haddad', title: 'Dr Haddad', timeZone: 'Asia/Riyadh', businessHours: { daysOfWeek: [7, 1, 2, 3, 4], start: '08:00', end: '12:00' } },
  ],
  events: [{ id: 'a', title: 'Visit', start: '2026-10-21T09:00[Europe/Paris]', resourceId: 'benali' }],
  onResourceProblems: (problems) => console.warn(problems),
});

// Later: another list.
calendar.update({ resources: [{ id: 'benali', title: 'Dr Benali' }] });
```

</Fragment>
<Fragment slot="angular">

```ts
import { Component } from '@angular/core';
import type { ResourceInput } from '@dzcalendar/core';
import { DZ_CALENDAR } from '@dzcalendar/angular';

@Component({
  selector: 'app-agenda',
  imports: [DZ_CALENDAR],
  template: `<dz-calendar timeZone="Europe/Paris" view="resourceTimeGridDay" [resources]="doctors" />`,
})
export class Agenda {
  readonly doctors: ResourceInput[] = [{ id: 'benali', title: 'Dr Benali' }, { id: 'haddad', title: 'Dr Haddad' }];
}
```

</Fragment>
<Fragment slot="react">

```tsx
import { DzCalendar } from '@dzcalendar/react';

const DOCTORS = [{ id: 'benali', title: 'Dr Benali' }, { id: 'haddad', title: 'Dr Haddad' }];

export function Agenda() {
  return <DzCalendar timeZone="Europe/Paris" defaultView="resourceTimeGridDay" resources={DOCTORS} />;
}
```

</Fragment>

<script setup lang="ts">
import { DzCalendar } from '@dzcalendar/vue';

const doctors = [{ id: 'benali', title: 'Dr Benali' }, { id: 'haddad', title: 'Dr Haddad' }];

Dans les frameworks, c'est une entrée : `resources` en Angular, en React et en Vue.
