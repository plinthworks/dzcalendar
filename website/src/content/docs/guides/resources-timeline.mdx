A **resource** is whatever events are booked on: a doctor, a room, a machine,
a batch job. Give the calendar a list of them and it draws one column per
resource (the grid views) or one row per resource (the Pro's timeline). Each
resource keeps its own business hours, read in its own time zone, and checks
its own rules.

## Giving resources

[`resources`](../../options/resources/) is a list of objects with an `id` and,
usually, a `title`. Any other field is yours: a service, a floor, a room
number. Events go on a resource with `resourceId` (see
[Events on resources](#events-on-resources)).

<CodeTabs>
<Fragment slot="js">

```ts
import { createCalendar } from '@dzcalendar/dom';
import type { EventInput, ResourceInput } from '@dzcalendar/core';

const doctors: ResourceInput[] = [
  { id: 'benali', title: 'Dr Benali' },
  {
    id: 'haddad',
    title: 'Dr Haddad',
    timeZone: 'Asia/Riyadh', // where its business hours are read
    businessHours: { daysOfWeek: [7, 1, 2, 3, 4], start: '08:00', end: '12:00' },
  },
];
const visits: EventInput[] = [{ id: 'a', title: 'Visit', start: '2026-10-21T09:00[Europe/Paris]', resourceId: 'benali' }];

const calendar = createCalendar(element, {
  timeZone: 'Europe/Paris',
  initialView: 'resourceTimeGridDay',
  resources: doctors,
  events: visits,
  onResourceProblems: (problems) => console.warn(problems),
});

// Later: another list (the same array again changes nothing).
calendar.update({ resources: doctors.slice(0, 1) });
```

Bad input never throws: a resource without an `id`, a duplicate, an unknown
parent or a cycle is reported to
[`onResourceProblems`](../../options/on-resource-problems/) and the rest is
drawn. The columns are in the calendar's zone; a resource's `timeZone` only
says where its hours are read, so a doctor in Riyadh open 08:00 to 12:00 is
shaded at 07:00 to 11:00 in Paris in October, and an hour later once Paris
falls back.

### Grouped, ordered, and an unassigned row

Resources come in the order given. To change that, name a field:

- [`resourceGroupField`](../../options/resource-group-field/) puts a head over
  each run of resources sharing that field's value;
- [`resourceOrder`](../../options/resource-order/) sorts them (`'title'`,
  `'-title'` for descending, `'floor,title'`, or a comparison function);
- [`showUnassigned`](../../options/show-unassigned/) adds a first row, or
  column, for events on no resource.

### A tree, and folding it

A resource with a `parentId` sits under its parent: a department above its
doctors. In a timeline, a branch folds. What is folded is kept by the
calendar, so it survives `update()`: read it with
[`onResourceToggle`](../../options/on-resource-toggle/) to keep it across
visits, and give it back with
[`collapsedResources`](../../options/collapsed-resources/) (and
[`collapsedGroups`](../../options/collapsed-groups/) for the group heads).

<CodeTabs>
<Fragment slot="js">

```ts
import { createCalendar } from '@dzcalendar/dom';
import '@dzcalendar/pro';

const saved = JSON.parse(localStorage.getItem('tree') ?? '{}') as { collapsedResources?: string[]; collapsedGroups?: string[] };

createCalendar(element, {
  timeZone: 'Europe/Paris',
  initialView: 'resourceTimelineWeek',
  resources: [
    { id: 'cardio', title: 'Cardiology' },
    { id: 'benali', title: 'Dr Benali', parentId: 'cardio' },
    { id: 'haddad', title: 'Dr Haddad', parentId: 'cardio' },
  ],
  ...saved,
  onResourceToggle: (state) => localStorage.setItem('tree', JSON.stringify(state)),
});
```

## Events on resources

An event goes on a resource with `resourceId`, or on several with
`resourceIds`: an event on two resources is drawn in both. Events on no
resource are not shown in a resource view, unless `showUnassigned` is on. A
drag from one resource to another swaps that resource for the new one and
keeps the others; a resize keeps them all. From code, `event.move` takes
`resourceIds` too.

<CodeTabs>
<Fragment slot="js">

```ts
import { createCalendar } from '@dzcalendar/dom';
import type { EventInput, ResourceInput } from '@dzcalendar/core';

const staff: ResourceInput[] = [
  { id: 'benali', title: 'Dr Benali', eventOverlap: false }, // no two of her events overlap
  { id: 'room1', title: 'Room 1' },
];
const events: EventInput[] = [
  { id: 'a', title: 'Consultation', start: '2026-10-21T09:00[Europe/Paris]', duration: { minutes: 45 }, resourceId: 'benali' },
  { id: 'b', title: 'Scan with Dr Benali', start: '2026-10-21T10:00[Europe/Paris]', duration: { hours: 1 }, resourceIds: ['benali', 'room1'] },
];

const calendar = createCalendar(element, {
  timeZone: 'Europe/Paris',
  initialView: 'resourceTimeGridDay',
  resources: staff,
  events,
  editable: true,
});

// Move the scan to the room alone, an hour later.
calendar.run({ type: 'event.move', id: 'b', start: '2026-10-21T11:00[Europe/Paris]', resourceIds: ['room1'] });
```

</Fragment>
</CodeTabs>

Each resource an event goes on checks, in its own zone, its own
`eventConstraint` and `eventOverlap` (the calendar's [`rules`](../../options/rules/)
apply where it says nothing). A refused drop is said to `onCommandRefused`
with what refused it.

## The timeline views of the Pro

The timeline puts resources in rows and time along. Its axis is elapsed time:
an event is as long on screen as it lasts, a 25-hour day is 25 hours wide and
a 23-hour day 23. The slots are cut on the wall clock, so on a fall-back night
02:00 appears twice. The timeline comes with `@dzcalendar/pro`: import it
once and its eight views are registered for every calendar made after. It is
MIT for now; there is no key.

| View | Default slot |
|---|---|
| `timelineDay`, `resourceTimelineDay` | 30 minutes |
| `timelineWeek`, `resourceTimelineWeek` | 1 hour |
| `timelineMonth`, `resourceTimelineMonth` | 1 day |
| `timelineYear`, `resourceTimelineYear` | 1 day |

The `resource…` views draw a row per resource; the others draw a single row
of every event. [`timeline`](../../options/timeline/) sets the scale
(`slot`, in minutes dividing a day, or `'day'`) and `maxLanes`, the lanes of a
row before "+N" holds the rest. The resource area's columns are
`viewOptions.timeline.areaColumns`, and
[`hooks.resource`](../../options/hooks/) draws a row's head.

## Supervision: a screen that watches the present

A timeline can also be a wallboard: processes in rows, what is running now at
the edge, new facts arriving by themselves, the screen left open for days. The
rest of this guide builds that, one piece at a time. Everything here is in the
`timeline` option and the event model; none of it needs a framework.

### Showing a span

A week of hours is too wide to read at a glance. [`timeline.span`](../../options/timeline/)
is the time on screen at once (`{ hours: 4 }`, `'PT1H'`, `{ days: 1 }`): the
slots share the room, whatever its width, so four hours fill a phone as they
fill a wide screen. A span longer than the period fits the period. A view of
your own, in `views`, can be a timeline of several days, with `span` showing a
part of it.

### Sliding by a step

By default ◀ ▶ change period. With `timeline.step` (`{ minutes: 15 }`,
`{ hours: 1 }`) they slide along the axis by that much instead, and at the end
of the axis the next or previous period comes in. Page Up and Page Down do the
same from the keyboard. For any other amount, `calendar.shift({ minutes: -45 })`
slides by it; a day or more is a period, not a shift.

### A ruler

`timeline.ticks` draws small marks inside each slot, as on a ruler:
`{ every: 1, label: 5 }` is a mark each minute and the time written every
fifth. A number is both. The marks are as dense as the room allows: with four
hours on screen, the marks alone.

### Following the present

[`timeline.follow`](../../options/timeline/) keeps the present in view as time
passes: `true` puts the present's slot at the left edge; the timeline moves on
when the next slot begins. Give it `{ before: { minutes: 5 } }` and the present
stays that far from the edge, a little of what just happened in view, the axis
gliding each minute (eased by the motion adapter, at once under reduced
motion). Following pauses as soon as the person scrolls, slides or changes
period, and "Today" takes it up again.
[`onFollowChange`](../../options/on-follow-change/) says when it pauses and
resumes: the place for a "Back to live" button. The line at the present, and
the axis with it, move once a minute by default;
[`nowRefresh`](../../options/now-refresh/) (`{ seconds: 5 }`) moves them more
often.

### Markers

An alert, a deployment, a threshold crossed: a moment, not a stretch. An event
with `display: 'marker'` has a start only; it is drawn as a line where it
happened with a flag carrying its title (an `end` or a `duration` given is
ignored, and said). It sits on its resource's row beside the runs, and
[`hooks.event`](../../options/hooks/) can write what the flag says. Next to
it, `display: 'background'` tints a stretch behind the runs, a maintenance
window for instance.

### Ongoing events

A run that has started and has not finished has no end to draw. Mark it
`ongoing: true`: it is drawn from its start to now and grows as time passes.
An `end` or a `duration` given on it is the length expected, drawn dashed past
now. When the run finishes, tell the calendar with `event.update` and
`ongoing: false`, with the real `end` if you have it, else it ends now. An
ongoing event is a timed event, not a series, and `forget` leaves it alone.

<CodeTabs>
<Fragment slot="js">

```ts
import { createCalendar } from '@dzcalendar/dom';
import '@dzcalendar/pro';

const calendar = createCalendar(element, {
  timeZone: 'Europe/Paris',
  initialView: 'resourceTimelineDay',
  resources: [{ id: 'backup', title: 'Backup' }],
  events: [
    // Started, expected to last 70 minutes, not finished.
    { id: 'run-1', title: 'Backup', start: '2026-10-21T09:00[Europe/Paris]', duration: { minutes: 70 }, resourceId: 'backup', ongoing: true },
  ],
});

// It finished, at the time the job reported.
calendar.run({ type: 'event.update', id: 'run-1', patch: { ongoing: false, end: '2026-10-21T10:12:40[Europe/Paris]', tone: 'green' } });
```

### Live sources

A screen like this is told, not asking.
[`liveSource`](../../options/sources/) (from `@dzcalendar/core/live`) opens a
feed you write (a WebSocket, an MQTT client, a timer) and hands each message
to `emit`; `sseSource` is the same for Server-Sent Events, with the browser
reconnecting a dropped stream. A message is one of:

| Message | Effect |
|---|---|
| `{ create }` | A new event |
| `{ update, patch }` | The patch laid over the event; `extendedProps` merged. `ongoing: false` without an end ends it now |
| `{ remove }` | The event is gone |
| `{ reset }` | The whole list again, as after a reconnection |

For `sseSource`, a `map` function turns each server message into one of these,
or `null` to ignore it.

<CodeTabs>
<Fragment slot="js">

```ts
import { createCalendar } from '@dzcalendar/dom';
import { liveSource, sseSource } from '@dzcalendar/core/live';
import type { LiveMessage } from '@dzcalendar/core/live';
import '@dzcalendar/pro';

// Server-Sent Events: a run starts, then ends.
const runs = sseSource('runs', '/api/runs/stream', {
  map: (data): LiveMessage | null => {
    const m = data as { kind: 'start' | 'end'; id: string; process: string; at: string; failed?: boolean };
    if (m.kind === 'start') return { create: { id: m.id, title: 'Run', start: m.at, resourceId: m.process, ongoing: true } };
    return { update: m.id, patch: { ongoing: false, end: m.at, tone: m.failed ? 'red' : 'green' } };
  },
});

// Any transport: a WebSocket.
const socket = liveSource('socket', {
  connect(emit) {
    const ws = new WebSocket('wss://example.com/runs');
    ws.onmessage = (e) => emit(JSON.parse(String(e.data)) as LiveMessage);
    return () => ws.close(); // called when the source is removed or the calendar destroyed
  },
});

createCalendar(element, {
  timeZone: 'Europe/Paris',
  initialView: 'resourceTimelineDay',
  resources: [{ id: 'import', title: 'Orders import' }],
  timeline: { span: { hours: 4 }, follow: true },
  sources: [runs, socket],
});
```

</Fragment>
</CodeTabs>

The feed is the authority: a person's edit to one of its events lasts until
the feed's next message. Keep the source objects in a constant, as a new object
is a new source, connected again.

### Forgetting the old

A screen left open for weeks must not grow for ever.
[`forget: { olderThan: { days: 2 } }`](../../options/forget/) removes, each
minute, the events that ended more than that long ago, from whatever source,
without an undo entry or an `onEventChange`. Ongoing events and series stay,
and a live source drops what the calendar forgot.

### Process heads

A row's head can say more than a title: how the last run went, how many
failed today, whether one is running now. The calendar's store tells what
changed through `kernel.subscribe`; read the events again, and give the
resources anew only when a summary differs: the heads redraw, nothing else.
[`hooks.resource.content`](../../options/hooks/) draws the head from the
resource's `extendedProps`.

<CodeTabs>
<Fragment slot="js">

```ts
import { createCalendar } from '@dzcalendar/dom';
import type { ResourceInput } from '@dzcalendar/core';
import '@dzcalendar/pro';

interface Summary {
  readonly running: boolean;
  readonly failures: number;
}

const processes: ResourceInput[] = [{ id: 'import', title: 'Orders import' }, { id: 'backup', title: 'Backup' }];

const calendar = createCalendar(element, {
  timeZone: 'Europe/Paris',
  initialView: 'resourceTimelineDay',
  resources: processes,
  timeline: { span: { hours: 4 }, follow: true },
  forget: { olderThan: { days: 2 } },
  hooks: {
    resource: {
      content: ({ resource }) => {
        const x = resource.extendedProps as Partial<Summary>;
        const box = document.createElement('div');
        box.textContent = `${resource.title ?? resource.id}${x.running ? ' · running' : ''}${x.failures ? ` · ${x.failures} failed` : ''}`;
        return box;
      },
    },
  },
});

let said = '';
function summarize(): void {
  const by = new Map<string, { running: boolean; failures: number }>(processes.map((p) => [p.id, { running: false, failures: 0 }]));
  for (const e of calendar.kernel.store.snapshot.allEvents()) {
    const s = by.get(e.resourceIds[0] ?? '');
    if (!s || e.allDay) continue;
    if (e.ongoing) s.running = true;
    else if ((e.props as { status?: string }).status === 'failed') s.failures++;
  }
  const resources = processes.map((p) => ({ ...p, extendedProps: by.get(p.id) }));
  const text = JSON.stringify(resources);
  if (text === said) return; // nothing differs: the heads are left alone
  said = text;
  calendar.update({ resources });
}

let queued = false;
calendar.kernel.subscribe((e) => {
  if (e.type !== 'store' || queued) return;
  queued = true;
  queueMicrotask(() => ((queued = false), summarize()));
});
summarize();
```

</Fragment>
</CodeTabs>

In Angular, React and Vue the head is a template (`dzResource`,
`renderResource`, `#resource`: see [`hooks`](../../options/hooks/)); the
summary is the same, computed from the events you already hold.
