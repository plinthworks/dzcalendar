The calendar dates are written in — the Hijri, the Persian — while the grid stays the same.

<OptionFacts name="displayCalendar" />

## What it does

Give one of the platform's calendars (`'islamic-umalqura'`, `'persian'`,
`'hebrew'`, `'buddhist'`…): titles, day numbers and labels are written in it;
the data, the days and the grids stay Gregorian — an event on 21 October is
on 21 October, written 10 Jumada al-awwal. Left out — or `null` — the
locale's own calendar (`ar-SA` has the Hijri one; engines differ there, so
write it); `'gregory'` forces the Gregorian. A name the platform does not
know throws a `RangeError`.

## Example

<CodeTabs>
<Fragment slot="js">

```ts
import { createCalendar } from '@dzcalendar/dom';

const calendar = createCalendar(element, { timeZone: 'Asia/Riyadh', locale: 'en-GB', initialView: 'dayGridMonth', displayCalendar: 'islamic-umalqura' });

// Later: the Gregorian (null would give the locale's own calendar back).
calendar.update({ displayCalendar: 'gregory' });
```

</Fragment>
<Fragment slot="angular">

```ts
import { Component } from '@angular/core';
import { DZ_CALENDAR } from '@dzcalendar/angular';

@Component({
  selector: 'app-agenda',
  imports: [DZ_CALENDAR],
  template: `<dz-calendar timeZone="Europe/Paris" displayCalendar="islamic-umalqura" />`,
})
export class Agenda {}
```

</Fragment>
<Fragment slot="react">

```tsx
import { DzCalendar } from '@dzcalendar/react';

export function Agenda() {
  return <DzCalendar timeZone="Europe/Paris" displayCalendar="islamic-umalqura" />;
}
```

</Fragment>
<Fragment slot="vue">

```vue
<script setup lang="ts">
import { DzCalendar } from '@dzcalendar/vue';
</script>

<template>
  <DzCalendar time-zone="Europe/Paris" display-calendar="islamic-umalqura" />
</template>
```

</Fragment>
</CodeTabs>

In the frameworks it is an Angular input (`displayCalendar`) and a React and Vue prop (`displayCalendar`, `display-calendar`).
